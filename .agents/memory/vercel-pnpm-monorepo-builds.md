---
name: Vercel pnpm monorepo builds
description: Non-obvious deployment constraints for legacy Vercel builds in a pnpm workspace
---

Legacy Vercel projects using a `builds` array may select pnpm by project age instead of the repository's `packageManager` field. Use Vercel's Corepack opt-in when the lockfile was generated by a newer pnpm major.

**Why:** A pnpm 9 installer rejected a valid pnpm 10 lockfile before application build steps ran, and legacy `builds` mode ignored a source-level `installCommand`.

**How to apply:** Confirm the selected pnpm version in deployment events. Keep application secrets unchanged; use the platform Corepack switch only with explicit approval.

Prebundle a monorepo API with the repository's validated build pipeline before a legacy `@vercel/node` handler imports it.

**Why:** Vercel's isolated TypeScript emit can leave workspace source imports unresolved at runtime even after the deployment reaches `READY`.

**How to apply:** Export the framework app separately from the standalone listener, import the generated app bundle from a small JavaScript handler, and include all generated runtime files in the function.

Legacy static builders mount output beneath the build source path rather than automatically at `/`.

**Why:** The generated index and assets returned 200 under the artifact path while public `/` and `/assets/*` returned 404.

**How to apply:** Rewrite public asset and metadata paths to the mounted artifact output, and point the SPA fallback at the mounted index file.

Vercel environment-variable names can exist with empty sensitive values.

**Why:** The deployment listed the Deriv and session keys, but the live preflight flags were all false and OAuth returned the exact missing-client error.

**How to apply:** Verify non-secret readiness flags through the app's preflight endpoint after environment changes; never assume a listed variable has a usable value.
